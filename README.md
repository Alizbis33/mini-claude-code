# mini-claude-code

> 一个在终端里对话的编程助手。**模型自主决定调用什么工具，代码负责执行，用户保留最终控制权。**
>
> 不用 LangChain，不用任何 Agent 框架 —— 基于 Node 原生 `fetch` 手写完整的工具调用闭环。
>
> **约 560 行 TypeScript ｜ 零第三方运行时依赖 ｜ 无构建步骤**

---

## 能力速览

| 能力 | 说明 |
|---|---|
| **工具调用循环** | 模型自主决定调用哪个工具、调用几次，直到给出最终答案 |
| **4 个内置工具** | `read_file` / `write_file` / `edit` / `run_command` |
| **路径沙箱** | 4 层纵深防御，把文件操作限制在工作目录内 |
| **权限系统** | 只读操作自动放行；写文件与执行命令**必须人工确认** |
| **上下文压缩** | 对话变长时自动摘要 —— 实测长对话 `prompt_tokens` 由 **13,761 降至 4,300 以内** |
| **API 容错** | 区分「可重试 / 不可重试」错误，对网络抖动与限流做指数退避重试 |
| **评测模式** | 环境变量切换到无人值守，导出指标 JSON 供批量评测 |

## 跑起来

### 前置条件

- **Node.js 22.9+**（`node --version` 检查）—— 依赖原生 TypeScript 类型擦除，无需构建工具
- 一个 DeepSeek API key（[platform.deepseek.com](https://platform.deepseek.com)）

### 三步

```bash
cp .env.example .env          # Windows PowerShell: Copy-Item .env.example .env
# 编辑 .env，填入 DEEPSEEK_API_KEY=sk-xxxxxxxx

node --env-file=.env Agent.ts
```

### 交互示例

```
你 > 读取 Agent.ts 并总结它的作用
模型 > 这是一个极简的 AI Agent……

你 > 它一共有多少行？
模型 > 约 560 行……

你 > 帮我把前五行写进 head.txt
⚡ 执行命令：
dir
允许吗？(y/n)
```

输入 `exit` 退出。

## 核心设计（要点）

**① 模型没有记忆，是你在替它记。**
LLM API 是无状态的。多轮对话的实现是：客户端维护 `messages` 数组，每轮把整段历史重发一遍；模型的回复本身就是一条 `{role:"assistant", content}`，可以直接塞回数组末尾。

**② 工具定义只有一个来源。**
每个工具是一个条目，包含描述、参数 Schema、执行逻辑、确认展示四部分。发给模型的 Schema 由它自动生成，执行时也从同一张表取 handler —— **加一个工具 = 加一个条目**，不会出现「改了一边忘另一边」。

**③ 路径沙箱是 4 层的。**
词法归一化 → 边界检查 → 真实路径解析 → 符号链接拒绝。其中第 ③ 层解析的是**父目录**而不是目标本身 —— 因为新建文件时目标还不存在，而父目录若指向外部，这一步足以暴露。

**④ 权限按破坏力分级，而不是按工具分级。**
只读操作自动放行，写文件和执行命令必须人工确认，未登记的工具一律拒绝（fail closed）。**确认信息的呈现由每个工具自己决定** —— 因为一刀切截断会让 shell 命令的后半截（真正危险的部分）被隐藏。

**⑤ 上下文成本是 O(N²) 的。**
每轮重发全量历史，聊 100 轮付的不是 100 份钱。解决方案是 compaction：把老对话交给模型总结成一段，替换掉原文。

## 已知限制

这份实现有几个**结构性边界** —— 不是没写完，而是这套做法做不到：

- **`run_command` 无法被路径沙箱约束。** 一条命令里可以有任意多个路径、可以用环境变量拼接、可以再套一层 shell，无法可靠地提取出它到底要碰什么。真正的隔离必须是操作系统级的（容器 / Windows Job Object + 低权限账户），纯 Node 层做不到。目前的策略是**强制人工确认 + 完整展示命令**，把最后一道防线放在人身上。
- **危险命令检测是黑名单** —— 只能提高门槛，不能保证安全。
- **反复压缩会导致摘要逐层退化** —— 这是所有 compaction 系统的通病。
- 没有流式输出，长回答时会"卡住"一段时间。
